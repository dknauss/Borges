# Markup-value results, Borges 1.17.0

Measured on the released Borges 1.17.0 (tag `v1.17.0`, commit 67bfffb), on
October 28, 2026, with the harness from `main` at 9024cc6. Between the tag and
9024cc6 only `tools/`, `docs/`, `.planning/`, and `CHANGELOG.md` changed, so
the plugin code is the release's; its PHP files are also byte-identical to the
1.17.0 ZIP on WordPress.org. Every measurement was made with `npm run all` and
`npm run sweep` for both corpora, as in [`2026-10-28.md`](2026-10-28.md), with
PHP 8.3, Node 22.22, AnyStyle 1.6.0, axe-core 4.11.0, and Lighthouse 13.5.0.

For the "Changed since 1.16.0" table, the same harness was run on `v1.16.0`
(commit 9fddeb9). 1.16.0 has no `bibliography_builder_add_list_roles()`, so
that one `render.php` call was skipped there; nothing else was changed.

Steps not rerun are listed at the end, with the reason. Their figures are not
repeated here.

notes-bibliography). Everything not listed came out the same on both versions,
including every AnyStyle and Borges-parser score below, the axe and
Lighthouse results, and the typed nodes, external identifiers, and `citation`
links on the twelve-work page.

The JSON-LD fact count falls because each `ListItem` no longer repeats its
work's `url`; the work keeps it. The four encyclopedia entries in the 36-work
list now carry their reference work as `isPartOf`, which adds the four
details. The COinS spans now say what kind of work each entry is (`rft.genre`)
and carry more of its fields, which is why Zotero's reader gets more right and
why the all-layers page is slightly larger gzipped.

## The page `citation` link without an SEO plugin

The harness models Yoast SEO, so it does not show the new `WebPage` node. To
check it, the twelve-work Borges page's block was saved into a post on
WordPress Playground (latest WordPress, PHP 8.3, no SEO plugin) with the 1.17.0
ZIP from WordPress.org. The page printed a `WebPage` node with 12 `citation`
links, each matching an `ItemList` entry's `@id`; no `ListItem` had a `url`;
and Adobe's validator found no errors or warnings.

## Not rerun

- **Language models** (`llm-baseline.mjs`) and **answering questions from the
  page**: both call Claude models, and no API key was available. The APA 7
  list these used was 1.16.0's, which printed "arXiv:arXiv:1706.03762"; 1.17.0
  prints the number once. The "printed" counts (65, 48, 126) were rerun and
  are unchanged.
- **Zotero translation server** (`npm run zotero-ts`): no Docker daemon was
  available, and installing the server from source was not allowed in this
  session. Zotero's own COinS reader, run by `measure.mjs`, was rerun (above).
- **Schema.org validator and Google's Rich Results Test on
  m.arginalia.com**: both are web tools, and on October 28 the live page still
  served 1.16.0-style markup (all 84 `ListItem`s with `url` and `item`), so it
  cannot show 1.17.0. The Playground check above stands in for it with Adobe's
  validator, which is not Google's test.

## Gaps

- Fixed in 1.17.0: the encyclopedia entries' container (130 of 130 in
  JSON-LD), the `ListItem` `url` that made Google read the list as a carousel,
  and the doubled "arXiv:" in APA 7 and IEEE.
- Still open: COinS has nowhere to put a web page's or a piece of software's
  publisher, so Zotero's reader recovers 123 of the 36-work list's 130
  details.
